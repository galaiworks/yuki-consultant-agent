# 計画: 講座生の相談を「傾向」として貯める(同意つき・匿名・人の承認つき)

担当: Codex(実装) / Claude Code(計画・検証・コミット・PR)
作業場所: `/Users/galaiworks/Desktop/yuki-consultant-agent.wt/yuki-student-insights`(ブランチ `agent/yuki-student-insights`)
承認: ガライさん(2026-11-19、設計案のとおり進める)

## 目的
講座生がそれぞれ YUKI AI を使う。相談の中身を、個人が分からない「全体の傾向」として貯め、
YUKI さんの講座・動画・回答の改善に使えるようにする。プライバシーを最優先にする。

## 絶対に守ること(受け入れ条件の前提)
1. **同意した人の会話だけ**を対象にする。初期値は「同意しない」。いつでも取り消せる
2. **ある講座生の具体的な話を、別の講座生への回答に使わない**(このフェーズでは、傾向を回答に混ぜる処理を作らない)
3. **個人を特定できる情報を残さない**: 名前・会社名・メール・電話・URL・住所・具体的な金額や人数は、傾向に書かない
4. **5 人以上**から同じテーマが出たものだけを残す(1 人だけの話は特定のおそれがあるので使わない)
5. **人の承認**を通ったものだけを「ナレッジ」にする(運営が承認。承認前は下書き)
6. 傾向の表・集計の元データは **service role だけ**が読み書きする(RLS で一般ユーザーからは見えない)
7. 本人が同意を取り消す、または退会したら、その人を元にした集計の記録を消し、人数を数え直す

## 変更範囲

### 1. データベース(新しいマイグレーション。既存は書き換えない)
- `profiles` に `insights_consent boolean not null default false` と `insights_consent_at timestamptz`
  - 本人は自分の同意だけを変えられる(既存の profile の RLS・列の保護に合わせる)
- `insight_topics`: 傾向 1 件
  - `id`, `theme`(短いテーマ。例「無料セミナーから本講座への申し込みが伸びない」), `pattern`(悩みの型の説明 1〜3 文), `category`(集客・商品・マインドセット・キャリア・お金・人間関係・その他), `user_count`(何人から出たか), `status`(`draft` / `approved` / `rejected`), `video_gap boolean`(YUKI さんの動画に答えが見つからなかったか), `created_at`, `updated_at`, `reviewed_by`, `reviewed_at`
- `insight_sources`: どの人のどの会話から出たか(人数の数え直しと、取り消し時の削除のためだけに持つ)
  - `topic_id`, `user_id`, `conversation_id`, `created_at`。一意制約 `(topic_id, user_id, conversation_id)`
  - 管理画面にも利用者の名前・メールは出さない(人数だけを出す)
- RLS: 両表とも有効化し、一般ユーザーのポリシーは作らない(service role のみ)

### 2. 同意の画面
- 新規登録(`/signup`)と「アカウント」画面に、同意のチェック(初期値オフ)
  - 文言: 「サービスの改善のため、個人が特定されない形で、相談の傾向(テーマ)を使うことに同意します。いつでも取り消せます。」
  - 何に使い、何に使わないか(別の人の回答には使わない、名前などは残さない)を 2〜3 行で添える
- アカウント画面で取り消すと、すぐに `insight_sources` からその人の行を消し、`user_count` を数え直す。5 人未満になった傾向は `draft` に戻すか消す

### 3. 傾向の取り出し(サーバーの処理)
- 管理画面のボタン「相談の傾向をまとめる」から実行(既存の `/api/jobs/run` の仕組みがあれば、週 1 回の自動実行も追加してよい)
- 対象: 同意している人の、前回の取り出し以降に更新された会話
- 1 会話ずつ、AI(`MODELS.worker`)で「テーマ」「悩みの型」「カテゴリ」だけを取り出す
  - 指示で個人情報を書かせない。さらにプログラムで、メール・電話・URL・数字の金額などを消す(二重の対策)
  - 既存のテーマに近ければ同じ傾向にまとめる(テーマの文字列か、AI に既存テーマの一覧を渡して選ばせる)
- YUKI さんの動画の検索(`searchKnowledge`)で関連が見つからないテーマは `video_gap = true`(=動画では答えていない質問。次の動画・講座のネタ)
- AI の費用は既存の利用料の記録に入れる(運営の費用として記録)
- `user_count` が 5 未満のものは、管理画面に出さない

### 4. 管理画面
- 「相談の傾向」の欄
  - 5 人以上の傾向を、人数の多い順に一覧(テーマ・悩みの型・カテゴリ・人数・動画で未回答か・状態)
  - 承認 / 却下のボタン。承認したものだけが「ナレッジ」
  - 承認済みの一覧を、YUKI さんに渡せる形(Markdown か CSV)で書き出す
- 利用者の名前・メール・会話の本文は出さない

### 5. プライバシーポリシー(`/privacy`)
- 利用目的に「同意を得た場合に限り、個人を特定できない形で相談の傾向を集計し、サービス・講座の改善に使う」を追加
- 同意の取り消し方、取り消したときに集計の元からも消すこと、5 人未満は使わないこと
- 「別の利用者への回答には使わない」
- 公開前に専門家の確認が必要な旨を、計画書と PR に書く(ポリシーの文面そのものには書かない)

## テスト方法
- 純粋な関数に切り出して単体テスト:
  - 個人情報の消し込み(メール・電話・URL・金額・人名らしき敬称つきの語)
  - 5 人以上だけを出す判定、取り消し後の数え直し
  - 同意していない人の会話を対象にしないこと
- `npx tsc --noEmit --incremental false` / `npm test` / `npm run build`
- 本番 DB へのマイグレーション適用は Codex は行わない(README の手順で、承認後に行う)
