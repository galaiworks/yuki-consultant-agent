# 計画: 入力の固定・会話ごとの履歴・文字の相談の自動読み上げ・待ち時間の表示

担当: Codex(実装) / Claude Code(計画・検証・コミット・PR)
作業場所: `/Users/galaiworks/Desktop/yuki-consultant-agent.wt/yuki-ui-sessions`(ブランチ `agent/yuki-ui-sessions`)

## 目的
YUKI さん本人に試してもらう前に、使い心地の詰まりを取る。とくに「待たされている」と感じさせないこと。

## 変更範囲と受け入れ条件

### 1. 入力欄・話すボタンを画面の下に固定する
- 相談画面(`src/app/chat`)の入力欄と送信ボタン、声の画面(`src/app/voice`)の話すボタンは、会話が長くなっても画面の下に固定され、スクロールで上に流れない
- 会話のログだけがスクロールする。新しい返事が来たら、ログは自動で一番下まで送る(ただし相談者が上を読んでいる間は勝手に送らない)
- 画面下のナビ(相談・声で話す・成果物…)と重ならない。iPhone の下端(safe-area)やキーボード表示時にも隠れない
- 受け入れ: スマホ幅(375px)とPC幅で、メッセージを 30 件並べても入力欄・話すボタンが常に見えて押せる

### 2. 会話ごとの履歴(Claude Code のセッションのように、1 つの話題 = 1 つの会話)
- 今は上部に直近 10 件の会話の小さなボタンが並ぶだけ。これを、会話の一覧(セッション一覧)にする
  - PC: 左の一覧。スマホ: ボタンで開く引き出し(ドロワー)
  - 各行: 会話の題名(最初の相談の冒頭)・最終更新の日時。いま開いている会話を強調
  - 一番上に「新しい相談」ボタン。押すと新しい会話が始まる
  - 新しい順に表示。50 件を超えたら「もっと見る」で続きを読む
- 声の画面で話した会話も、同じ一覧に入る(声の会話には小さな目印)。一覧から選ぶと、その会話の続きを文字でも声でも続けられる(声の画面も `?c=<会話ID>` で続きを開けるようにする)
- 会話は本人のものだけが見える(既存の RLS のまま。service role で一覧を読まない)
- 受け入れ: 会話を 3 つ作り、一覧から行き来して、それぞれの履歴が混ざらない

### 3. 文字で相談したときも、YUKI が書き出しと同時に話し始める
- 相談画面に「声で聞く」の切り替え(初期値オン。選択は端末に覚えさせる。`appConfig.voiceEnabled` がオフなら出さない)
- オンのとき、返事の文字が流れ始めたら、文が 1 つ区切れた時点でその文から読み上げを始める(全文を待たない)
- 実装は、声の画面の返事(`src/app/api/voice/turn/route.ts`)で使っている仕組みをそのまま使い回す: サーバー側で返事の文字の流れを `SentenceSplitter` で文に区切り、`synthesize` で音声にして、チャットの流れ(`src/app/api/chat/route.ts` のイベント)に音声のイベントとして載せる。リクエストに「声で聞く」かどうかを渡す
  - 任意の文章を読み上げる新しい入口(API)は作らない(悪用されると読み上げの費用がかかるため)
  - 読み上げの費用は既存の `recordSpeechUsage` で記録し、月の上限に数える
  - 読み上げは返事の最初の 2500 文字まで(既存の上限と同じ)
- ブラウザでは受け取った音声を順に再生する。Safari・iPhone で鳴るように、送信ボタンを押したときに音声の再生を許可しておく(既存の声の画面のやり方を使う)
- 再生中は止めるボタンを出す。新しく送ったら、前の読み上げは止める
- 受け入れ: 「声で聞く」オンで送ると、最初の文が表示されてからおおむね数秒以内に声が始まる。オフなら鳴らない

### 4. 待ち時間を感じさせない表示
- 送信した瞬間に、YUKI の吹き出しを出す(サーバーの返事を待たない)
- 吹き出しの中に、考えている様子を出す。打っているような動き(…)と、短い一言
  - 一言は、サーバーから届く状況(`status` イベント。例:動画の中から関係する話を探しています)があればそれを使う
  - 届くまでの間は、YUKI らしい一言を数秒ごとに入れ替える(例:「ちょっと考えてますね」「いい質問ですね、整理してみます」「関係しそうな話を思い出しています」)。同じ言い回しを続けない
- 返事の文字が届いたら、その一言を消して本文に置き換える
- 声の画面でも、話し終えてから返事が届くまでの間、同じ吹き出しを出す
- 吹き出しの一言は「AI であることを隠す」ものにしない(人のふりをする言い回し、例「今ロサンゼルスから返信しています」は使わない)
- 受け入れ: 送信から返事の最初の文字までの間、吹き出しが空白になる瞬間がない

## 守ること
- デザインは黒×ゴールド(`src/lib/ui-black-gold.md`)に合わせる
- 秘密情報(service role キー・API キー)をクライアント側に出さない
- 画面に出す AI 表示・注意書きは消さない
- 既存のテスト・型を壊さない。純粋な関数にできる部分(例:考え中の一言の選び方、会話一覧の並べ方)は関数に切り出してテストを書く
